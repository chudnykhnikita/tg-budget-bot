# SSH-доступ к общему серверу с Happ

Проверено 10.11.2026 на Mac владельца, сервер `83.166.245.224`.

- Работать со включённым **Happ**. Не отключать VPN и не переключать пользователя на MantaRay или другой клиент.
- Исключение IP в Happ не обеспечило рабочий SSH: TCP открывался, но данные не приходили. Привязка сокета к физическому интерфейсу `en0` дала SSH-баннер за 0,1 с; вход по ключу и выкладка складского бота прошли успешно.
- Перед SSH проверить баннер: `nc -b en0 -w 5 83.166.245.224 22`. Ожидается `SSH-2.0-OpenSSH...`. Успешный TCP connect сам по себе не подтверждает SSH и не доказывает блокировку IP. При отсутствии баннера не повторять входы в цикле.
- Команда входа: `ssh -o ConnectTimeout=15 -o 'ProxyCommand=nc -b en0 %h %p' root@83.166.245.224`.
- Для копирования: `scp -o ConnectTimeout=15 -o 'ProxyCommand=nc -b en0 %h %p' <file> root@83.166.245.224:<project-path>/`.
- `en0` проверен именно на этом Mac. При смене сети/компьютера сначала определить физический интерфейс; не подставлять интерфейс VPN `utun*`.
- Перед использованием multiplex-соединения проверить существование сокета (`ssh -S <socket> -O check root@83.166.245.224`). Фоновая master-сессия может не сохраниться между вызовами инструмента; на новых соединениях обязательно сохранять ProxyCommand. Для серии операций можно использовать одну непрерывную SSH-сессию.
- Существующие `deploy.sh` могут вызывать SSH/SCP без ProxyCommand: перед запуском учитывать это и выполнять соответствующие команды с указанной опцией. Эта документация не меняет сами скрипты.
- Сервер общий для нескольких проектов: менять только контейнеры, файлы и данные текущего проекта. Сохранять его собственный порядок деплоя, Docker-сеть, тома и переменные окружения. SSH-маршрут на Mac не заменяет настройки MTU/прокси внутри сервера.
